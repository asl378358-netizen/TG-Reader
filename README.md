# TG Reader

Собирает сообщения, фотографии, голосовые и кружочки из выбранных Telegram-групп вашего аккаунта. Сохраняет материалы в синхронизируемую папку Google Диска. Смысловую ежедневную сводку читает и составляет ChatGPT после подключения папки.

## Установка один раз

1. Скачать **TG-Reader-Setup.cmd** и запустить двойным щелчком.
2. Установщик использует уже установленный Python 3.10–3.14 x64. Он не скачивает новый Python. Ранее установленное окружение сборщика используется повторно, если зависимости подходят.
3. На рабочем столе и в меню «Пуск» появится **TG Reader**. Дальше запускать этот ярлык.

Архивы вручную распаковывать не нужно. После успешной установки исходный установочный файл можно убрать: копия остаётся в папке программы.

## Первый сбор

1. Полностью закрыть Telegram Desktop через значок возле часов → «Выход». Прокси/VPN оставить работающим.
2. Нажать **«Подключить Telegram / выбрать группы»**.
3. Выбрать свой `tdata`, аккаунт и одну группу для проверки. Сначала `tdata` открывается без локального кода; если это возможно, лишнего запроса пароля нет. При необходимости программа просит код блокировки Desktop на этом компьютере и позволяет исправить ввод. Облачный пароль двухэтапной проверки запрашивается отдельно после выбора аккаунта. Пароль виден по умолчанию; окно показывает число символов и Caps Lock/раскладку.
4. Выбрать синхронизируемую папку Google Диска, период чтения и типы вложений для каждой группы. Нажать **«Собрать сейчас»** и **«Открыть состояние»**.
5. Проверить файлы в браузерном Google Диске. После проверки можно включить автосбор.

Короткие ограничения Telegram (одна пауза до 5 минут, суммарно до 10 минут
на основном соединении) обрабатываются внутри текущего сбора: окно показывает
отсчёт, затем повторяется тот же запрос без повторного входа или новой пагинации.
Это относится к истории сообщений и скачиванию медиа. Длительная пауза сохраняется
между запусками и показывается со временем в часовом поясе из настроек
(по умолчанию Europe/Berlin). Короткая пауза, сохранённая прежней версией,
отсчитывается перед подключением. Уже полученные сообщения и медиа сохраняются.
Окно различает успешный, частичный и приостановленный сбор.

## Период чтения и вложения

Кнопка **«Период и медиа»** меняет настройки без повторного входа в Telegram.
Период: последние 1, 3, 7, 14, 30 или 90 суток. По умолчанию — 3 суток;
в окне и журнале показана конкретная дата начала. Первый сбор читает этот
период, следующие продолжают с сохранённого места. При расширении периода
добавляются недостающие сообщения без дублей. После долгого перерыва программа
читает выбранный период, пропуская более старую историю.

В таблице каждой группы отдельно включаются **фото**, **голосовые** и **кружочки**.
Текст, подписи и ссылки сохраняются всегда; обычные видео не скачиваются.
Изначально все три типа включены. Для новостного канала можно выключить все
вложения, а для учебной группы оставить нужные. Поиск по выбранным группам
сохраняет галочки, даже когда строка скрыта фильтром.

Старые родительские сообщения нужны для понимания ответов: их текст и ссылки
сохраняются, но вложения вне выбранного периода не скачиваются. Выключенные и
слишком старые задания убираются из активной очереди и счётчика остатка.
Уже подготовленные файлы сохраняются для повторного включения. Уменьшение
периода не удаляет ранее сохранённые файлы: это ограничение новых скачиваний,
а не автоматическая очистка диска.

Большое число после **«ID сообщения»** — номер в Telegram, а не количество
скачанных сообщений. Количество показано отдельно как новые сообщения и контекст.

В этом же окне можно выбрать другую папку выгрузок. Выбирайте локальную копию
папки **TelegramDailyReader**, синхронизируемую приложением Google Диск, либо её
родительскую папку: программа не создаёт второй одноимённый каталог внутри уже
выбранного TelegramDailyReader. Следующий сбор заново публикует доступные дневные
пакеты в выбранную папку. Прежние выгрузки остаются на месте.
Разовая загрузка ZIP через браузер не включает синхронизацию будущих файлов.

Дневной индекс сообщает ошибки и полноту чтения. Для непрочитанного пустого дня
не создаётся пустой ZIP, который можно принять за успешную выгрузку. При чтении
агент должен использовать индекс, а не наличие старых архивов рядом с ним.

## Скорость и первая расшифровка

История читается страницами до 100 сообщений, с интервалом 1 секунда между
страницами. Это не фиксированная скорость: сеть, размер ответа и ограничения
Telegram влияют на результат. Пауза 30 секунд означает ожидание повторного
запроса, а не получение одного сообщения каждые 30 секунд.

В окне видны общее число сохранённых новых сообщений, контекст, число новых
сообщений за последние 30 секунд и текущий этап. Этот счётчик учитывает ожидание
Telegram; контекст и проверка правок не увеличивают число новых сообщений.
Журнал дополнительно показывает запрошенное и возвращённое количество записей
для каждого запроса истории/сообщений.

Сведения о медиа запрашиваются порциями до 100 сообщений одной группы.
Файлы скачиваются отдельно; повторная обработка сохранённого оригинала не
создаёт новых запросов Telegram. Бюджет по умолчанию — 100 медиа за сбор;
оставшиеся задания сохраняются для следующих запусков.

При первой расшифровке скачивается публичная модель `small`. Токен/аккаунт
Hugging Face не нужен. Статус подготовки появляется каждые 10 секунд и показывает
время ожидания и размер папки модели на диске; это не процент скачивания.
Предупреждение о ссылках Windows заменено понятным статусом. Ошибки загрузки
остаются ошибками, пишутся в журнал и оставляют оригиналы для повторной попытки.
Неудачная подготовка модели не запускает её скачивание заново для каждого
голосового в одном сборе. Следующий сбор может повторить попытку.

## Поиск и фильтры групп

После первого входа используйте **«Изменить выбранные группы»**: вход, сеанс и
папка Google Диска используются повторно. Отмена сохраняет прежнюю настройку.

- Поиск по части названия, нескольким словам, @username, ссылке t.me или ID.
- Тип: группы, группы с темами или каналы.
- Архив: все чаты, без архива или только архив.
- Дата последнего сообщения: 7/30/90 дней, старше 90 дней или неизвестна.
- Только непрочитанные, только выбранные; сортировка по дате, имени или непрочитанным.
- Недоступные, покинутые и перенесённые чаты по умолчанию скрыты. Их можно
  показать для проверки, но выбрать для сбора нельзя.

Поиск и фильтры работают локально по полученному списку и не создают дополнительных
запросов Telegram. Выбор сохраняется при смене фильтров и страниц; счётчик показывает
скрытые выбранные чаты. Список отображается страницами по 300 записей, с прокруткой.
«Давность» относится к последнему сообщению, не к дате вашего посещения группы.

API ID/hash собственного приложения Telegram не требуются. Платный AI API не используется.

## Обновления

При запуске ярлыка и перед сбором программа проверяет ветку **stable** этого репозитория. Короткие сбои сети не мешают запуску установленной версии.

Новая версия скачивается отдельно, проверяет размеры/SHA256 файлов и совместимость зависимостей. Только после проверки переключается активная версия. Предыдущий код и окружение остаются на компьютере; ошибка скачивания или проверки не удаляет их. Настройки, авторизация и сообщения хранятся отдельно от кода.

Репозиторий **публичный**: обновления скачиваются без входа в GitHub. Для приватных
копий поддерживается уже сохранённый доступ GitHub CLI или Git Credential Manager;
новое окно входа в браузере не открывается. Файлы Telegram и личные сообщения
в этот репозиторий не загружаются.

## Файлы и расписание

В `%LOCALAPPDATA%\TelegramDailyReader` находятся программа, окружения Python, журналы и локальные данные. Удаление старой распакованной папки на рабочем столе их не затрагивает. Удаление этой папки AppData удалит локальную авторизацию и базу сообщений.

«Включить автосбор» создаёт задачу Windows: каждые 30 минут и после входа в Windows, пока пользователь вошёл в систему. Запуск проверяет обновления, собирает новые сообщения и дополняет дневные пакеты. Выключенный компьютер сообщения не собирает.

Журналы: `setup.log`, `launcher.log`, `collector.log`, `last-collection.log`.
`last-collection.log` сохраняет вывод последнего ручного или планового сбора.
`collector.log` показывает этап, название RPC-запроса, секунды ограничения и
решение о повторе. Запросы целиком и ключи авторизации в него не записываются.
Пароли, `tdata`, `.auth.enc` и конфигурацию пересылать не требуется.

## Для разработки

`main` — рабочий код. GitHub Actions проверяет Windows/Python и установщик, затем переводит прошедший проверки коммит в `stable`. Пользовательские обновления идут только из `stable`.

Перед коммитом: `python tools/build_setup.py`. Проверки: `python -m unittest discover -s tests -p "test_*.py"`, `tests/test_installer.ps1`, `tests/test_bootstrap.ps1`.
