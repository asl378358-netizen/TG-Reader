Telegram Daily Reader 0.2.0 — вход через локальный Desktop
Дата: 2026-10-05

В этой версии выполнено в Linux, Python 3.12:
- 25 автоматических проверок: все прошли (18 проверок прежнего сборщика + 7 новых).
- Настоящий парсер opentele2 1.2.1 загрузил искусственно созданный tdata:
  сохранены user ID, DC и все 256 байт тестового ключа; сетевого входа не было.
- tdata с локальным код-паролем читается; неверный пароль вызывает отказ.
- Ожидание QR-подтверждения регистрируется ДО подтверждения токена.
- Двухэтапная проверка и ошибка входа проверены на имитации клиента.
- Связь авторизации с выбранным аккаунтом проверяется до чтения групп.
- Файл авторизации не может быть прочитан вне локальной папки данных.
- Запись и повторная загрузка проходят через границу шифрования DPAPI;
  сам DPAPI в Linux имитируется, его работа на Windows еще не проверена.
- Три новые зависимости имеют готовые wheel для Windows x64 / CPython 3.12.

НЕТ проверки живого входа в аккаунт владельца.
НЕТ проверки живого Telegram Desktop конкретной версии на Windows.
НЕТ проверки синхронизации и доступа ежедневного агента к новой папке Drive.
НЕТ гарантии, что сервер Telegram примет вход со встроенными реквизитами.

При первом запуске программа НЕ включает расписание сама.
Первый пилот: одна группа, ручной сбор, статус, проверка тем и медиа,
сводка по новым выгрузкам. Затем расписание и расширение до 10 групп.

Ни настоящие tdata, ни сеанс, ни пароли, ни личные сообщения в ZIP не включены.
Библиотека читает tdata локально. Исходный Desktop-сеанс не сохраняется и
не завершается; отдельный новый сеанс сборщика зашифрован через DPAPI.
Отмененная настройка пытается завершить только новый сеанс сборщика.

голосового и фото не повторялось в этой версии: обработчик не менялся.
